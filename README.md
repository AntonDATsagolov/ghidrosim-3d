# ГидроСимулятор 3D

Гидродинамическое моделирование и расчёт массопереноса при **подземном
скважинном выщелачивании (ПСВ) урана**. Программа строит трёхмерную
геологическую модель пласта по скважинным данным, рассчитывает поле
напоров и линии тока, моделирует выщелачивание урана серной кислотой и
считает запасы в закисляемом объёме.

Функциональный аналог программного комплекса «Симулятор 3D»
(ТОО «ИВТ» + НИИ «КазНТУ» им. К.И. Сатпаева, заказчик — АО НАК «Казатомпром»)
и MacroMine: геологический модуль (интерполяция), гидродинамический модуль
(поле давления, линии тока, граничные условия Неймана и Дирихле) и модуль
химической кинетики (ВР, ПР, остаточный уран, подсчёт запасов).

## 1. Быстрый старт

```bash
cd "программа с тимой"
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# библиотека three.js для 3D-вида (скачивается один раз, проверяется по SHA-256)
python3 scripts/fetch_vendor.py

# запуск сервера и открытие браузера
.venv/bin/python backend/app/cli.py --port 8000
```

Программа откроется на `http://127.0.0.1:8000`. Нажмите **«Расчёт»** —
модель уже настроена на демонстрационный блок.

Скрипт `Запустить.command` выполняет все эти шаги сам: создаёт окружение,
устанавливает зависимости, подгружает three.js и открывает браузер.

Для macOS есть готовый launcher:

```bash
./Запустить.command
```

Тесты:

```bash
.venv/bin/python -m pytest backend/tests -q
```

## 3. Физическая модель

### 3.1 Геологическая модель

Скважинные данные (коэффициент фильтрации, пористость, содержание урана,
доля глины, литология) интерполируются на расчётную сетку:

* **ординарный кригинг** (вариограммы: сферическая, экспоненциальная,
  гауссова, линейная; учитывается нуджет и анизотропия);
* **обратные взвешенные расстояния** (IDW).

Результат отсекается диапазоном исходных данных — интерполяция не должна
давать проницаемость или содержание урана вне наблюдаемых значений.

### 3.2 Гидродинамика

Решается стационарное уравнение Дарси в трёх измерениях:

```
div(k · grad(h)) + q = 0
```

* `h` — напор, м; `k` — коэффициент фильтрации, м/сут; `q` — объёмный
  расход, м³/сут.
* Дискретизация — конечные объёмы по граням, проводимость между
  соседними ячейками — гармоническое среднее.
* **Граничные условия задаются по каждой из шести граней блока:**
  * Неймана — непроницаемая грань;
  * Дирихле — заданный напор: вода входит в блок или выходит из него
    (взаимодействие с региональными грунтовыми водами).
* Скорость потока в порах: `v = (k/φ)·grad(h)`.
* **Анизотропия**: коэффициент `k_z / k_xy` (по умолчанию 0,2) — для
  осадочных рудных пластов горизонтальная проницаемость обычно выше
  вертикальной.
* При замкнутых границах и несбалансированных расходах избыток раствора
  распределяется по внешним граням блока (модель утечки через границы);
  это отражается в отчёте о балансе.

### 3.3 Линии тока

Трассировка методом РК4 по полю скоростей, старт — из ячеек фильтров
закачных скважин, остановка — в ячейках отборных скважин, на границе блока
или в застойной зоне. По линиям тока рассчитывается **время пребывания
раствора**, что даёт оценку скорости выщелачивания.

### 3.4 Химическая кинетика и массоперенос

Основные реакции:

```
UO2 + H2SO4      -> UO2SO4 + H2O
2Fe³⁺ + UO2      -> 2Fe²⁺ + U(VI)
```

Скорость растворения урана (смешанный контроль — реагент 1-го порядка,
твёрдая фаза 1/3):

```
R = (k1·C_a + k2·C_Fe3) · U_отн^(1/3) / (1 + β·C_Fe(OH)3)
```

Потери урана: `k3` — осаждение, `k4` — сорбция на глине.
Температурная поправка — уравнение Аррениуса.
Стехиометрия: 2,0 кг H₂SO₄ и 0,47 кг Fe(III) на 1 кг растворённого урана.

Перенос растворённых веществ — адвекция (upwind-схема по граням) +
диффузионно-дисперсионный член (продольная дисперсия 0,05 м +
молекулярная 0,01 м²/сут) + химические реакции. Шаг по времени
ограничивается условием устойчивости по адвекции и диффузии.

Отслеживаются три поля:
* **ВР** — концентрация кислоты в выщелачивающем растворе, г/л;
* **ПР** — концентрация урана в продуктивном растворе, мг/л;
* **ОМ** — остаточный уран в руде, кг/т.

### 3.5 Запасы

В закисляемом объёме (ячейки, где кислотность выше порога) и внутри
пользовательского контура считаются:

* суммарный запас урана, т;
* объём закисляемых ячеек, м³;
* площадь в плане, га;
* средневзвешенное содержание урана, кг/т;
* средняя мощность рудного пласта, м;
* средневзвешенный метропроцент.

## 5. Работа с программой

### 5.1 Загрузка данных

Кнопка **«Импорт данных»** — файл CSV (разделитель определяется
автоматически, кодировки UTF-8 / Windows-1251 / KOI8-R) или XLSX.
Столбцы сопоставляются автоматически (в том числе по русским названиям:
«Скважина», «Коэффициент фильтрации», «Уран», «Дебит», «Тип» и т. д.);
сопоставление можно поправить вручную перед загрузкой.

Распознаваемые поля:

| Поле | Что означает |
|---|---|
| `name` | наименование скважины |
| `x`, `y`, `z` | координаты устья и отметка фильтра |
| `k` | коэффициент фильтрации, м/сут |
| `porosity` | пористость |
| `uranium` | содержание урана, кг/т |
| `clay` | доля глинистой компоненты (0…1) |
| `lithology` | литология (текст) |
| `rate` | дебит, м³/сут (закачка `+`, отбор `−`) |
| `well_type` | `injection` / `production` / `observation` |
| `acid_in` | кислотность ВР на входе, г/л |
| `screen_top`, `screen_bottom` | интервал фильтрации, м |

Загруженные значения попадают и в список скважин, и в набор свойств пласта
(интерполяция использует их как исходные точки).

### 5.2 Расчёт

1. **Геология** — метод интерполяции, модель вариограммы, радиус
   корреляции, анизотропия (в том числе `k_z/k_xy`).
2. **Границы** — для каждой из шести граней блока: Неймана или Дирихле
   с заданным напором.
3. **Кинетика** — кислотность реагента, Fe(III), Fe(OH)₃, температура,
   коэффициенты `k1…k4` и `β`, время интегрирования. Отдельно задаются
   коэффициенты для расчёта **вдоль линий тока** (`k1*…k4*`).
4. **Расчёт** — кнопка «▶ Расчёт» в шапке.

Результаты: поле напоров, скорости, линии тока, срезы по любому полю и
слою, кривые ПР/ВР, кривая накопленного извлечения, запасы.

### 5.3 Калибровка коэффициентов скоростей реакции

Значения `k1…k4` по умолчанию — ориентировочные. Их следует подобрать так,
чтобы **расчётная кривая ПР совпала с фактической** по эксплуатационному
блоку (как в методике исходного ПО):

1. внести фактические концентрации урана в ПР и кислотности ВР по датам;
2. подобрать `k1` (основная скорость) по нарастанию концентрации урана в ПР;
3. подобрать `k3`, `k4` — по спаду концентрации после выхода на плато;
4. учесть `β` при наличии кольматации (Fe(OH)₃).

Расчёт по линиям тока (вкладка «Линия тока») даёт независимую оценку:
по времени пребывания раствора и остаточному урану в руде вдоль линии.

## 7. Сторонние зависимости

`frontend/vendor/` (three.js r187, MIT) **не входит в репозиторий** —
файлы скачиваются скриптом `scripts/fetch_vendor.py` и проверяются по
SHA-256. Без них расчёты, кривые и карта среза работают, но 3D-сцена
не отображается.

## 8. Проектные файлы

Проект сохраняется в один файл `.s3dp` (zip-архив):

```
project.json   состав проекта: сетка, скважины, свойства, параметры
arrays.npz     расчётные поля (напор, скорость, кислотность, уран и др.)
```

## 9. Что нужно от заказчика

Для перехода с учебных данных на реальный блок (например, 5-2-1
месторождения Северный Карамурун) нужны:

1. **Выгрузка из БД «Атомгео» / системы «Рудник»** по скважинам блока:
   координаты, отметки, интервалы фильтрации, категория скважины.
2. **Скважинные данные пласта**: коэффициент фильтрации, пористость,
   содержание урана, литология — с указанием, к какой отметке относится
   замер (интерполяция ведётся в 3D).
3. **Режим работы скважин**: дебиты по периодам (или один типовой режим),
   кислотность подаваемого раствора.
4. **Фактические кривые ПР и ВР** по блоку (даты, концентрация урана в ПР,
   кислотность ВР) — для калибровки `k1…k4`.
5. **Граничные условия**: есть ли региональный градиент грунтовых вод,
   утечка раствора за пределы блока (тогда — грани Дирихле с напорами).

Формат файла — CSV или XLSX с колонками по списку из раздела 5.1;
при необходимости сопоставление столбцов правится прямо в интерфейсе.

## 10. Ограничения и развитие

* Модель стационарная по гидродинамике (один режим работы скважин);
  для этапной отработки с разными режимами требуется переход к
  последовательным расчётам по стадиям (`RateStage` в модели уже есть,
  используется в API).
* Учитываются только две основные реакции выщелачивания; расход кислоты
  на карбонаты и глину задаётся косвенно (коэффициентом `k1`) — при
  наличии данных по карбонатности его следует учитывать отдельной
  поправкой к `k1`.
* Модель не учитывает тепловой прогрев блока (температура — параметр).
* Интеграция с БД «Атомгео» выполняется через промежуточный файл
  выгрузки; прямого подключения к СУБД предприятия нет.

## 11. Проверка корректности

Автоматические тесты (`backend/tests`) проверяют:

* дискретную неразрывность гидродинамического решения (сумма расходов по
  граням плюс источник равна нулю в каждой ячейке);
* баланс расходов «закачка − отбор = 0»;
* поведение граничных условий Неймана и Дирихле;
* консервативность переноса растворённых веществ без реакций;
* расход кислоты и высвобождение урана при реакции;
* влияние температуры (Аррениус) и кольматации;
* материальный баланс урана (извлечённое + находящееся в растворе ≤
  начального запаса);
* воспроизведение исходных данных кригингом и IDW;
* корректность подсчёта запасов и построения контура;
* автоматическое сопоставление столбцов при импорте;
* полный конвейер на демо-проекте.
